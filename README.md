# 人格工坊（astrbot_plugin_persona_studio）

在聊天里就能养人格：**对话中新建人格 → 随时切换 → 不满意直接让 LLM 改**；同时提供函数调用工具，**让 LLM 自己读取所有人格**。

插件基于 AstrBot 内置的 `PersonaManager` / `ConversationManager` 开发，新建的人格与 WebUI「人格」页面里的数据完全互通（在聊天里建的，后台能看到、能编辑）。

## 功能

| 指令 | 说明 |
| --- | --- |
| `/人格` | 列出所有人格，✅ 标注当前会话正在使用的人格 |
| `/人格创建 <名称> <描述>` | 在对话中新建人格。描述会由 LLM 扩写成完整的系统提示词，创建后默认自动切换 |
| `/人格切换 <名称>` | 随时切换当前会话的人格，群聊 / 私聊各自独立；用 `/人格切换 默认` 还原默认人格 |
| `/人格修改 <名称> <要求>` | 让 LLM 按你的要求重写这个人格的提示词（也可写 `/人格修改 当前 <要求>`，改当前会话的人格） |
| `/人格查看 [名称]` | 查看人格的完整系统提示词 |
| `/人格删除 <名称>` | 删除人格 |

指令只有中文名（含 `/人格列表`、`/创建人格`、`/新建人格`、`/切换人格`、`/修改人格`、`/人格调整`、`/查看人格`、`/删除人格` 等中文别名），**不注册 `persona` / `persona_*` 英文别名**，避免与 AstrBot 内置指令（旧版本的 `/persona`）或其他插件冲突。LLM 工具名 `persona_list` / `persona_read` / `persona_current` 属于函数调用命名空间，与聊天指令不冲突，保持不变。

## 使用示例

```text
用户：/人格创建 猫娘 一只傲娇的猫娘，说话带喵，喜欢被摸头
Bot：✅ 已创建人格「猫娘」（已由 LLM 扩写为完整系统提示词）
     📝 系统提示词预览：你是一只名叫…… 
     🎉 已自动切换到该人格，直接聊天即可生效。

用户：你好呀
Bot：（以猫娘人格回复）

用户：/人格修改 猫娘 再傲娇一点，每句结尾都要有“喵”，讨厌被叫笨蛋
Bot：✅ 已按你的要求用 LLM 重写人格「猫娘」。

用户：/人格切换 默认
Bot：✅ 已切换到人格「默认」，本会话后续回复都会使用它。
```

- 想直接用自己写的提示词、不让 LLM 改：`/人格创建 客服 --raw 你是一个专业的客服……`
- 改当前会话的人格：`/人格修改 当前 <修改要求>`；要求里没有空格时也可以整段不写名字，如 `/人格修改 说话更简洁一点`
- 用便宜模型聊天、用强模型写人格：在插件配置里把「人格扩写/修改使用的模型」选成某个模型提供商即可（`/人格创建` 的扩写和 `/人格修改` 的重写都会用它）
- 名字打错不会误改人格：`/人格修改 诗入 说话要押韵`（「诗人」写错）会**只回复提示、列出所有现有人格 ID，不修改任何人格**。首 token 形如人格名（合法字符、不含标点）时按名字处理；只有当整段没有空格分隔的名字、或首 token 明显是句子（带标点）时，才当作「改当前会话人格」

## 配置项

在 AstrBot 后台「插件管理 → 人格工坊 → 配置」中修改：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `manage_requires_admin` | `true` | 创建 / 修改 / 删除人格是否需要管理员权限。切换人格不受限制 |
| `allow_private_chat_manage` | `true` | 私聊中允许非管理员管理人格（群聊仍需管理员） |
| `use_llm_expand` | `true` | 创建时用 LLM 把描述扩写成完整提示词 |
| `persona_llm_provider` | 空 | **人格扩写 / 修改用哪个模型**。留空 = 跟随当前会话正在使用的对话模型；也可以在下拉框里选一个已配置好的模型提供商（适合「用便宜模型聊天、用强模型写人格」） |
| `auto_switch_after_create` | `true` | 创建成功后自动切换到新人格 |
| `max_show_length` | `1500` | 回显提示词的最大字符数，超出截断 |
| `enable_llm_tools` | `true` | 注册 LLM 读取人格的函数调用工具（见下节），关闭后模型无法读取人格提示词 |
| `llm_tool_max_chars` | `4000` | LLM 工具单次返回提示词的截断长度，避免撑爆上下文 |

> LLM 相关功能（扩写、修改）默认使用**当前会话正在使用的对话模型**；在配置里指定 `persona_llm_provider` 后改用该模型。如果没配置可用的模型提供商，插件会给出提示，并退回“直接使用你的描述”。所选模型若已被删除 / 禁用，会自动回退为当前会话模型并在日志中告警。

## 让 LLM 读取人格（函数调用工具）

插件注册了三个**只读**函数调用工具，模型在对话中可自行调用（无需用户敲指令），从而"看到"所有人格：

| 工具 | 参数 | 作用 |
| --- | --- | --- |
| `persona_list` | 无 | 列出**所有**人格：ID、提示词字数、提示词摘要，并标注当前会话正在使用的人格 |
| `persona_read` | `persona_id` | 读取指定人格的**完整系统提示词**；ID 不存在时返回候选列表便于模型自我纠正 |
| `persona_current` | 无 | 读取当前会话生效的人格及其完整提示词（能区分「未指定 / 已关闭 / 已被删除」） |

效果举例：

```text
用户：都有哪些人格？
Bot：（调用 persona_list）现在有 3 个人格：猫娘、诗人、客服……

用户：诗人这个人格具体是怎么设定的？
Bot：（调用 persona_read，persona_id=诗人）它的设定是：你是一位浪漫的诗人……
```

说明：

- 工具默认开启；在后台插件配置里把 `enable_llm_tools` 关掉即可禁用（此时工具会返回“已被管理员关闭”）。
- 只读：这三个工具**不会**创建 / 修改 / 删除 / 切换人格，不会产生副作用。
- 工具返回内容受 `llm_tool_max_chars` 限制，超长提示词会截断并标注总字数。
- 若在后台「扩展 → 组件」里对工具单独设置了权限，以那里的设置为准（`persona_*` 三个工具名）。
- 想让模型也能**改**人格（切换 / 新建 / 修改），可以按同样的方式再加写操作工具。

## 实现要点

- 新建 / 修改人格：`self.context.persona_manager.create_persona()` / `update_persona()`，写入 AstrBot 数据库，与 WebUI 共享。
- 切换人格：写入当前会话的「对话人格」（`conversation_manager.update_conversation(persona_id=...)`，没有对话时会自动新建），保证只影响本会话，不污染其他群。
- 切换时会顺带清掉该会话可能存在的「会话级强制人格」（`session_service_config.persona_id`），否则它会覆盖对话人格，导致切换看起来不生效。
- `/人格切换 默认` 会解析 AstrBot 当前配置的默认人格；若配置里没有真实人格，则回退为「不使用人格」。
- LLM 返回内容会做清洗（去代码块围栏、去「系统提示词：」前缀），避免把多余文字写进人格。
- 扩写 / 修改用哪个模型：`_resolve_llm_provider()` 先看配置 `persona_llm_provider`，为空才用 `get_using_provider_async(umo)`；因此聊天模型和「写人格」的模型可以分开。取模型时先试 `Context.get_provider_by_id()`，失败再退回 `provider_manager.inst_map`（不同 AstrBot 版本两者不一定都在），避免静默用错模型。
- 配置的模型不可用（被删 / 被禁用 / 版本不兼容取不到）时不会报错中断：自动回退当前会话模型，并在 `/人格修改`、`/人格创建` 的回执里用 `⚠️` 明确写出来，同时在日志里告警。`/人格` 列表里也会显示当前「扩写/修改人格使用的模型」。
- `/人格修改` 的参数解析：首 token 形如人格名（名称合法、不含句子标点）时按名字处理，查无此人就只回提示、不修改任何人格；只有整段没有空格分隔的名字，或首 token 明显是句子（含标点）时，才当作「改当前会话人格」。
- LLM 工具用 `@filter.llm_tool(name=...)` 注册，参数在 docstring 的 `Args:` 里用 `参数名(string)` 声明（AstrBot 据此生成 JSON Schema），框架调用约定是 `handler(event, **kwargs)`，返回的字符串会被回灌给模型作为工具结果。

## 安装

把 `astrbot_plugin_persona_studio` 整个文件夹放到 AstrBot 的 `data/plugins/` 下（或在插件管理页选择本文件夹 / 压缩包安装），重载插件即可。

## 测试

插件自带两套离线测试（用假的 Context / 假 LLM，不写真实数据库、不调真实模型）：

```bash
pip install astrbot                  # 测试只依赖 astrbot 本体
python tests/test_main.py            # 100+ 项断言：指令分支、权限、参数解析、LLM 工具、边界
python tests/test_integration.py     # 真实 PersonaManager + SQLite + SharedPreferences + 工具调用约定
```

- `tests/test_main.py`：把假 Context / 假 LLM 注入插件，覆盖全部指令（含「人格名打错只提示、不误改当前人格」）、三个 LLM 工具的返回内容与异常分支。
- `tests/test_integration.py`：用真实 `PersonaManager`、`ConversationManager`、SQLite 和
  `SharedPreferences`（都在临时目录里）跑完整链路，并用 `resolve_selected_persona`
  确认「切换后 AstrBot 真的会按新人格回复」、确认 LLM 修改真的落库；同时按
  `functools.partial(handler, 插件实例)` 复刻框架的绑定方式，验证 LLM 工具「event + kwargs」
  的真实调用约定可用。
- 两个测试都会把 AstrBot 运行根目录指向临时目录（`ASTRBOT_ROOT`），不会污染插件目录或真实数据目录。

## 依赖

无第三方依赖，仅使用 AstrBot 内置接口（要求 AstrBot v4.x，已在 4.28.1 上验证）。
